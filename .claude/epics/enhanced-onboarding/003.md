# Task: Build onboarding PageView skeleton with navigation

## Description
Rewrite `OnboardingPage` as a `PageView` with 5 steps, progress dots, back button, and skip handling. Each step is a placeholder widget initially (colored containers with step labels). Wire up `completeOnboarding()` on any exit path (skip or completion), including `authStateNotifier.updateAuthState(onboardingCompleted: true)` to trigger the router redirect to home.

## Acceptance Criteria
- [ ] `OnboardingPage` renders a `PageView` with 5 placeholder steps
- [ ] Progress dots indicator shows current step (1-5)
- [ ] Back button available on Steps 2-4 (not Step 1)
- [ ] "Skip" action available on Steps 1, 3, 4 — marks onboarding complete and navigates to home
- [ ] Step 2 has no skip (informational only, just "Continue")
- [ ] Any skip or completion path calls `completeOnboarding()` with tracking fields
- [ ] Any skip or completion path calls `authStateNotifier.updateAuthState(onboardingCompleted: true)` to trigger router redirect
- [ ] Page transitions are smooth horizontal slides
- [ ] Back navigation preserves step state (PageView handles this naturally)
- [ ] All steps responsive from 320dp through tablet
- [ ] Define all state variables and callback signatures in skeleton so Tasks 004/005/006 only create their own widget files

## Technical Details
- File: `lib/features/auth/presentation/pages/onboarding_page.dart` (major rewrite)
- Use `PageController` with `physics: NeverScrollableScrollPhysics()` (no swiping — button-driven only)
- Local state: `_currentStep` int, form data variables, pairing/creation result booleans
- Progress indicator: row of 5 dots, filled up to current step
- Skip logic: call `completeOnboarding(devicePaired: _devicePaired, itemCreated: _itemCreated)` then `authStateNotifier.updateAuthState(onboardingCompleted: true)`
- Step 5 (Done) is conditional: only show if both `_devicePaired` and `_itemCreated` are true; otherwise skip straight to home
- The `authStateNotifier` is already available in the widget tree — access it the same way the current onboarding page does
