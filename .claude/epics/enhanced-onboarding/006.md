# Task: Implement Step 4 (Create First Item) and Step 5 (Done)

## Description
Build simplified item creation form (name + goal + count-per-press) with use-case-based pre-filled suggestions. Build conditional Done screen showing device name and item name. Wire item creation through existing `ItemRepository.createItem()` and device sync.

## Acceptance Criteria
- [ ] Step 4 shows: item name (required), goal (optional), count per press (default: 1)
- [ ] Item name pre-filled based on Step 1 use case selection:
  - Inventory → "Stock Count"
  - Habit → "Water Intake"
  - Fitness → "Push-ups"
  - Manufacturing → "Units Produced"
  - Other/skipped → empty
- [ ] "Create" button calls `ItemRepository.createItem()` and syncs to device
- [ ] "Skip" option available — marks onboarding complete, goes to home
- [ ] If device not connected (user skipped Step 3): Step 4 is skipped entirely
- [ ] Step 5 only shown when both device pairing AND item creation completed
- [ ] Step 5 shows device name and item name as confirmation
- [ ] Step 5 "Get Started" button marks onboarding complete and navigates to home
- [ ] If either Step 3 or Step 4 was skipped: go straight to home (no Step 5)
- [ ] Uses `AppColors` and `Theme.of(context).textTheme` — no hardcoded styles
- [ ] Proper `Semantics` labels on all interactive elements
- [ ] Touch targets at least 48dp
- [ ] Responsive from 320dp through tablet

## Technical Details
- Step 4: simplified version of `ItemFormPage` — only name, goal, incrementBy fields
  - Use same `ItemRepository.createItem()` call as the full form
  - After creation, sync item to device via `BluetoothBloc` if connected
  - Set parent state `_itemCreated = true` on success
- Step 5: conditional display
  - Only render if `_devicePaired && _itemCreated`
  - Show device name (from `BluetoothBloc` state) and item name
  - "Get Started" calls completion flow
- Use case suggestions passed from Step 1 via parent state
- `deviceItemId` assignment: first item for a new user gets `deviceItemId: 0` — verify `ItemRepository.createItem()` handles this automatically via next-available-ID logic
