# Task: Bluetooth Pages

## Description

Create the 3 bluetooth pages (connection initiation, search, device management) and wire them to the existing BluetoothBloc for ESP32 device connectivity.

## Acceptance Criteria

- [ ] Connection initiation page at `/bluetooth` (when not connected)
- [ ] Bluetooth search page at `/bluetooth/search`
- [ ] Device management page at `/bluetooth/device` (when connected)
- [ ] Scan for ESP32 devices works
- [ ] Device list shows available devices
- [ ] Connect to device works
- [ ] Disconnect from device works
- [ ] Send items to device works
- [ ] Send selected item to device works
- [ ] Connection state persists across navigation
- [ ] Bluetooth tab in nav bar shows correct page based on connection state

## Technical Details

### Files to Create
- `lib/features/bluetooth/presentation/pages/bluetooth_page.dart` - Connection initiation
- `lib/features/bluetooth/presentation/pages/bluetooth_search_page.dart` - Device scanning
- `lib/features/bluetooth/presentation/pages/device_management_page.dart` - Connected device

### Files to Modify
- `lib/core/router/app_router.dart` - Add bluetooth routes

### Existing Assets
- `BluetoothBloc` at `lib/features/bluetooth/presentation/bloc/`
- Bluetooth use cases (scan, connect, disconnect, send_items, etc.)
- `flutter_blue_plus` already configured

### Page Specs (from FF)

**Connection Initiation (bluetooth_page.dart)**
- Prompt to connect device
- Button to start scanning
- Bluetooth permission handling

**Bluetooth Search (bluetooth_search_page.dart)**
- List of discovered devices
- Device name and signal strength
- Tap to connect
- Scanning indicator

**Device Management (device_management_page.dart)**
- Connected device info
- Disconnect button
- Device status
- Last sync time

### Implementation Steps
1. Create connection initiation page with BluetoothBloc
2. Create bluetooth search page with device list
3. Create device management page with disconnect option
4. Add routes to AppRouter
5. Implement routing logic (show search vs management based on state)
6. Test with real ESP32 device

### Key Considerations
- Bluetooth permissions must be requested
- Connection state determines which page shows
- Error handling for connection failures
- Handle device disconnection gracefully
