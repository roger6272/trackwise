# Task: Firmware: OTA Data Characteristic + Commands + State Machine + Rollback

## Description
Add OTA Data write-with-response characteristic for receiving binary chunks, implement ota_start/ota_end/reboot commands on existing command channel, build OTA state machine (IDLE→RECEIVING→VERIFYING→VERIFIED→REBOOTING) with timeouts and incremental SHA256, and add rollback protection.

## Acceptance Criteria
- [ ] OTA Data characteristic (UUID ...9011) on existing custom service, write-with-response
- [ ] ota_start command accepted: validates battery ≥20%, transitions to RECEIVING
- [ ] Binary chunks received on OTA Data characteristic, written directly to flash
- [ ] Incremental SHA256 computed via mbedtls_sha256 as chunks arrive (no RAM buffering)
- [ ] ota_end command: compares computed hash with expected, transitions to VERIFIED or returns hash_mismatch
- [ ] reboot command: triggers esp_restart() after marking new partition bootable
- [ ] 30s inactivity timeout in RECEIVING state → returns to IDLE
- [ ] 10s auto-reboot timeout in VERIFIED state
- [ ] Button presses ignored and "updating" shown on display during OTA states
- [ ] esp_ota_mark_app_valid_cancel_rollback() called at end of setup() after all peripherals confirmed
- [ ] Low battery returns error response to ota_start when SOC < 20%

## Technical Details
- OTA Data characteristic UUID: 12345678-1234-1234-1234-123456789011
- State machine: IDLE → RECEIVING → VERIFYING → VERIFIED → REBOOTING
- Commands on existing command characteristic (JSON): ota_start (with expected_size, expected_hash), ota_end, reboot
- Notifications for responses: ota_ready, ota_progress, ota_verified, ota_error(reason)
- Incremental SHA256 using mbedtls_sha256_context
- createService handle count: currently ~10, OTA Data adds 2 = 12 (fits in 15 default)
- Rollback: esp_ota_mark_app_valid_cancel_rollback() at end of setup()
