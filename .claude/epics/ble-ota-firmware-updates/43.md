# Task: App: OTA Data Layer — Firebase Datasource, Version Comparison, BLE Transfer

## Description
Build the OTA feature's data and domain layers following clean architecture in lib/features/ota/. Includes: Firebase datasource (Storage download + Remote Config fetch), BLE datasource (OTA writes using DeviceConnection), FirmwareInfo entity and model, OTA repository, CheckForUpdate use case (version comparison), and PerformOtaUpdate use case (sync + download + transfer + verify orchestration).

## Acceptance Criteria
- [ ] lib/features/ota/ structure created following clean architecture
- [ ] FirmwareInfo entity: version, sha256, changelog, min_app_version, file_path, released_at
- [ ] FirmwareInfoModel: latest.json deserialization
- [ ] OtaRemoteDatasource: fetch latest.json from Firebase Storage, fetch min_firmware_version from Remote Config
- [ ] OtaBleDataSource: write binary chunks to OTA Data characteristic using write-with-response
- [ ] OtaRepository: abstract + implementation combining datasources
- [ ] CheckForUpdate use case: compare device version vs latest, determine optional/required/up-to-date
- [ ] Version comparison: hand-rolled semver (split on '.', compare integers), handles 1.9.0 vs 1.10.0
- [ ] PerformOtaUpdate use case: sync-before-OTA → download → send ota_start → chunk transfer → ota_end → reboot
- [ ] Sync-before-OTA calls existing sync infrastructure, waits for completion
- [ ] App version gate: CheckForUpdate checks min_app_version against current app version
- [ ] Remote Config falls back to hardcoded min_firmware_version when unreachable
- [ ] OTA chunk sizing uses DeviceConnection.negotiatedMtu
