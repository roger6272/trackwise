# Task: Testing: Unit Tests — Version Comparison, OtaBloc States, CheckForUpdate

## Description
Write unit tests for the OTA feature's critical logic: version comparison edge cases, OtaBloc state transitions, and CheckForUpdate use case scenarios (newer/forced/up-to-date/offline). Integration tests (rollback, timeout, hash mismatch) require physical hardware and are tracked separately.

## Acceptance Criteria
- [ ] Version comparison tests: 1.0.0 < 2.0.0, 1.9.0 < 1.10.0, 2.0.0 > 1.99.99, equal versions, malformed input handling
- [ ] OtaBloc state transition tests: full happy path (Idle→Available→Downloading→Transferring→Verifying→Rebooting→Complete)
- [ ] OtaBloc error states: timeout, hash mismatch, disconnect, low battery, cancel
- [ ] CheckForUpdate use case: newer version available (optional), forced update (below min), up-to-date (no update), offline fallback
- [ ] App version gate: min_app_version > current app version → app update needed
- [ ] Tests use mocktail (project standard, not mockito)
- [ ] All tests pass with flutter test

## Technical Details
- Test files:
  - test/features/ota/domain/usecases/check_for_update_test.dart
  - test/features/ota/domain/usecases/perform_ota_update_test.dart
  - test/features/ota/presentation/bloc/ota_bloc_test.dart
  - test/features/ota/data/models/firmware_info_model_test.dart
- Use mocktail for mocking (project standard)
- Follow existing test patterns (see test/features/items/ for reference)
- Version comparison edge cases are critical — 1.9.0 vs 1.10.0 is a common bug
- OtaBloc tests should verify state machine transitions match expected sequence
- Integration tests (hardware-dependent) are out of scope for this task
