# Task: Firmware - Override chunking and sync_complete

## Description

Implement the override protocol (receiving chunked item data from app) and sync_complete command (updating sync_seq after normal sync). This completes the firmware multi-device protocol.

## Acceptance Criteria

- [ ] override_start handler: store sync_seq, total_chunks, clear all items
- [ ] override_chunk handler: save items to slots, increment received count
- [ ] Enforce 100 item limit (device_item_id must be 0-99)
- [ ] override_end handler: validate chunks, set selected_id, update sync_seq, respond
- [ ] sync_complete handler: update sync_seq, send acknowledgment
- [ ] Error response if chunks missing at override_end
- [ ] Display "SYNCED" after successful override
- [ ] Exit conflict state after successful override
- [ ] 10-second timeout on all commands

## Technical Details

### Override Protocol
```cpp
// override_start: { "cmd": "override_start", "sync_seq": 43, "total_chunks": N }
// override_chunk: { "cmd": "override_chunk", "index": 0, "items": [...] }
// override_end: { "cmd": "override_end", "selected_id": 2 }
// Response: { "status": "override_complete" } or { "status": "error", "message": "missing_chunks" }
```

### Item Fields in Override
- device_item_id, name, category, count, todaycount
- increment, reminder, reminder_value, lastResetTime, reset_number

### sync_complete Protocol
```cpp
// App sends: { "cmd": "sync_complete", "sync_seq": 43 }
// Response: { "status": "seq_updated" }
```

### selected_id Behavior
- If selected_id doesn't exist in items → fall back to first item (index 0)
- If no items at all → select nothing
