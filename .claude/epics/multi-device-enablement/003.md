# Task: Firmware - Handshake protocol and conflict state handling

## Description

Implement the handshake BLE command that combines account lock check and sync sequence comparison, plus the conflict state UI behavior (SEE APP display, disabled buttons).

## Acceptance Criteria

- [x] Handshake command handler implemented
- [x] Account lock check: reject if paired_uid doesn't match
- [x] First pairing: store uid if paired_uid is empty
- [x] Sync sequence comparison: return in_sync or conflict
- [x] Three response types: in_sync, conflict, wrong_account
- [x] Display "PAIRED TO OTHER ACCOUNT" on wrong_account response
- [x] Conflict state: display "SEE APP", disable increment/decrement
- [x] Exit conflict state on BLE disconnect
- [x] Button press in conflict state shows "SEE APP" reminder

## Technical Details

### Handshake Protocol
```cpp
// App sends: { "cmd": "handshake", "uid": "xxx", "sync_seq": 42 }
// Responses:
// - { "status": "in_sync", "device_instance_id": "uuid" }
// - { "status": "conflict", "device_seq": N, "device_instance_id": "uuid" }
// - { "status": "wrong_account", "device_instance_id": "uuid" }
```

### Conflict State
- Global flag: inConflictState
- enterConflictState(): set flag, display "SEE APP", disable buttons
- exitConflictState(): clear flag, enable buttons, clear display
- onDisconnect(): exit conflict state if active
- onButtonPress(): if in conflict, show "SEE APP" and ignore

### Account Lock Logic
1. If paired_uid not empty AND != incoming uid -> wrong_account
2. If paired_uid empty -> store uid, proceed
3. Compare sync_seq -> in_sync or conflict
